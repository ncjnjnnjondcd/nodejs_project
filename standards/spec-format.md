# Стандарт інженерної специфікації (spec-format)

Будь-яка архітектурна специфікація проєкту (`spec.md`) повинна містити такі обов'язкові розділи:

## 1. Мета і межі системи
- Призначення системи та межі контексту.
- Технологічний стек бекенду та формат клієнта.
- Чіткий перелік того, що не реалізується.

## 2. Компоненти та взаємодія
- Таблиця компонентів із зазначенням файлів і зон відповідальності.
- Каскадний потік викликів: рух запиту від DOM/fetch до бази даних.

## 3. Модель даних
- Опис сутностей, їхніх ключів (PK, FK) та типів даних.
- Суворе визначення переліків enum для статусів і пріоритетів.

## 4. Контракт REST API
- Префікс маршрутів `/api/...`, методи (GET, POST, PATCH, DELETE).
- Валідація вхідних параметрів і схеми DTO.
- Коди відповідей (200, 201, 400, 404).

## 5. Критерії прийняття (DoD)
- Наскрізна типізація: заборона числових приведень (`+id`).
- Обов'язкова валідація DTO через `class-validator`.
- Повна узгодженість між схемою БД, специфікацією та README.
