# 0002. Організація статичного аналізу та Git-хуків

* **Status:** accepted
* **Date:** 2026-10-28
* **Authors:** Мартинюк Максим ІО-44

## Контекст і проблема
Необхідно запобігти потраплянню синтаксичних і типових помилок у репозиторій перед комітом.

## Критерії рішення
* Швидкість виконання аналізу.
* Блокування некоректного коду до потрапляння в репозиторій.

## Розглянуті варіанти
* **Варінт 1:** ESLint v9 Flat Config для всього проєкту.
* **Варінт 2:** Oxlint + Prettier у lint-staged (pre-commit) та збірка з тестами у pre-push.

## Рішення
Вибраний варіант: **Варіант 2**, оскільки Oxlint забезпечує швидкий розбір AST, а lint-staged перевіряє виключно індексовані файли.

## Наслідки
* Плюси: Миттєва перевірка під час коміту.
* Мінуси: Специфічні правила фреймворку валідуються на етапі npm run build.
